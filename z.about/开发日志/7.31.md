## 二、Bug 修复清单（37 项）

### 2.1 功能缺陷修复（16 项）

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 筛选栏无重置按钮 | `ReviewRecordList`/`OperationLogs` 缺失重置逻辑 | 新增 `[重置]` 按钮，清除全部筛选条件并重新查询 |
| 2 | 检索维度切换缺失 | 前端仅支持"全部字段"检索 | `SearchHome` 新增检索维度下拉（全部/题名/档号/责任者/主题词），传 `dimension` 参数到后端 |
| 3 | 搜索结果目录树不可选 | 节点渲染为文本框而非可选择组件 | 改为 `el-tree` 三级复选框（门类→年度→部门），`scope_nodes` 全链路贯通 SE-002 |
| 4 | 关键词+筛选走 keyword 导致筛选失效 | SQLite `_fallback_search` 未处理高级筛选参数 | 扩展 `_fallback_search` 支持 year_from/year_to/category/department/fonds_id/fonds_ids/author/file_code 全部 8 个筛选参数 |
| 5 | 预审记录重复入库 | `preview` 端点每次调都 INSERT 新记录 | 改为 **upsert**：同 `archive_id` 更新不新增；列表接口去重取最新 |
| 6 | 审核建议档位与原型不符 | 输出 3 档（建议开放/部分开放/不开放） | 改为 4 档：建议开放 / 建议部分开放（脱敏后）/ 建议延期开放 / 建议不开放，更新 `review_service.py`/`llm_client.py`/`seed.py`/前端常量 |
| 7 | 统计页 reviewer 可见全部用户数据 | `by-user`/`by-time`/`by-type` 无权限过滤 | 新增 `_apply_stats_scope`：非 admin 角色只能看自己的数据 |
| 8 | 统计 API 5xx 时页面显示虚构数据 | `catch` 块中返回 mock 回退数据 | 失败时全部显示 0 + 红色错误横幅，移除所有虚构回退 |
| 9 | 操作日志失败数始终为 0 | 前端按 `operation_type=failure` 查，实际存 `result` 字段 | 后端 `by-type` 新增 `failed` 计数（`WHERE result='failure'`） |
| 10 | 预审记录筛选值不匹配 | UI 选项（建议部分开放）与实际存储值（建议人工重点关注）不一致 | `suggestion` 下拉改为实际输出值，中/高风险筛选不再筛空 |
| 11 | 日志描述过于简略 | 中间件仅记录 `POST /api/xxx` | 重构：GET→"查看XX页面"，POST→"XX操作"；检索/AI预审端点传自定义描述 |
| 12 | 登录失败日志用户显示 anonymous | 中间件取不到用户名 | auth 端点设置 `request.state.log_username`，中间件优先读取 |
| 13 | 旧日志无清理机制 | 日志表无限增长 | 启动时 `_cleanup_old_logs()` 删除 >180 天记录 |
| 14 | `OperationLog.target_id` 始终为空 | 中间件未提取操作对象 | 从 URL 正则提取 + `request.state.log_target_id` 自定义 |
| 15 | 日志可被直接篡改 | 无完整性校验 | SHA256 哈希链：每条日志 `chain_hash = SHA256(prev_hash + content)`；新增 `/audit/chain-verify` 校验端点 |
| 16 | 同步任务无操作日志 | 同步完成不记录 | `_log_sync_op`：完成时以"系统"用户写入 `OperationLog`，含哈希链 |
