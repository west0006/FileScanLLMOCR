## 一、风险评分与开放建议（6.5 开放审核功能）

| 项 | 方案书要求 | 当前实现 | 差异 |
| --- | --- | --- | --- |
| 评分区间 | 0-20 低 / 21-60 中 / 61-100 高 | 0-20 低 / 21-45 中 / 46-70 中 / 71-100 高 | 阈值切分不同（代码 4 档） |
| 低风险建议 | 建议开放 | 建议开放 | ✓ |
| 中风险建议 | **建议人工重点关注**（L809）/ 建议延期（L811） | 建议部分开放（脱敏后） | ✗ 措辞不同 |
| 高风险建议 | **建议延期开放或不予开放**（L809） | 建议不开放 | ✗ 代码拆成「延期/不开放」两值 |

方案书 L811 明确定义建议三值：**建议开放 / 建议延期 / 建议不予开放**。
当前代码 `review_service.hybrid_review` 生成四值（多「建议部分开放（脱敏后）」）。
→ 影响预审记录页「AI 建议」筛选、预审详情展示、导出列。

## 五、修复优先级调整建议

按方案书校准，需新增/调整的修复项：

1. **预审建议枚举对齐**（高）：建议三值「建议开放 / 建议延期 / 建议不予开放」；风险阈值改为 0-20 / 21-60 / 61-100 三档。
2. **日志操作对象 target_id 覆盖**（高）：检索、审核、导出等操作补写 target_id，满足七要素。
3. **角色下拉对齐**（中）：核心 3 角色，「查档人员」按学校需求保留或移除。
4. **检索字段权重**（低）：标题权重 3.0 → 2.0（可选）。

> 注：方案书「建议延期开放或不予开放」为高风险档的完整措辞，与测试用例的筛选下拉组合选项一致；代码当前拆成「建议延期开放 / 建议不开放」两个独立值，导致筛选口径不一致。
