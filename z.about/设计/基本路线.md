## 二、前端 —— 7 个模块，79 个功能点

按详细功能清单，你需要实现的页面：

### 模块一：智能检索（最核心，23 项功能）

```
页面清单：
├── 检索首页（搜索框 + 目录树选范围 + 层级选择）
├── 检索结果页（列表 + 高亮 + 关联度值 + 分类筛选 + 排序/分页）
├── 档案详情页（元数据 + 原文在线浏览 + OCR文本对照浏览）

├── 检索历史面板

**关键实现点：**
- 三种检索模式切换：关键词 / 语义（自然语言输入）/ 高级组合

- 原文浏览：TIFF/JPG/PDF 在线预览（可用 `pdf.js` + 图片查看器）
- OCR 对照浏览：左右分屏，原文图像 ↔ OCR 文本
- 关键词高亮 + 关联度百分比显示（参照知网风格）

```
页面清单：
├── AI 预审工作台（左右分栏：档案原文 | AI 风险面板）

### 3.2 核心 API 设计

#### 检索 API (`/api/search`)
```
POST /api/search/keyword       # 关键词检索
POST /api/search/semantic      # 语义检索（调 LLM 理解意图 → ES 查询）
POST /api/search/advanced      # 高级组合检索
GET  /api/search/history       # 检索历史
GET  /api/archives/{id}        # 档案详情
GET  /api/archives/{id}/ocr    # OCR 文本对照
POST /api/search/export        # 结果导出
```

#### OCR 任务 API (`/api/ocr`)
```
POST /api/ocr/tasks            # 创建任务
GET  /api/ocr/tasks            # 任务列表
GET  /api/ocr/tasks/{id}       # 任务详情 + 进度
PUT  /api/ocr/tasks/{id}       # 暂停/恢复/取消
GET  /api/ocr/results/{id}     # 识别结果查看
GET  /api/ocr/quality-report   # 质量报告
```

#### AI 预审 API (`/api/review`)
```
POST /api/review/tasks         # 创建预审任务（异步：→ Celery）
GET  /api/review/tasks         # 任务列表
GET  /api/review/tasks/{id}    # 任务进度 + 各风险等级分布
GET  /api/review/records       # 预审记录列表（支持筛选）
GET  /api/review/records/{id}  # 记录详情（12 字段）
POST /api/review/export        # 导出预审结果 Excel + 原文压缩包
```

#### 预审核心流程（后端调度）
```
用户创建任务 → Celery 队列 → 逐件推给 LLM 推理 → 
LLM 返回 {risk_score, risk_level, sensitive_items, suggestion, reason} →
写入 MySQL 预审记录表 → 更新任务进度
```

### 3.3 关键后端要点

| 要点 | 实现 |

## 四、AI 微调与训练 —— 这是你最重的工作

### 4.1 OCR 引擎微调（PaddleOCR）

**目标：印刷体 ≥99%，清晰手写体 ≥85%，复杂版式 ≥90%**

```
步骤：
1. 数据收集
   ├── 从现有档案扫描件中抽样（不同年代/门类/版式）
   ├── 覆盖：印刷体、手写体、表格、印章覆盖、破损、模糊
   └── 标注：文本行位置 + 文本内容（可用 PPOCRLabel 工具）

2. 数据预处理
   ├── 图像增强：去噪 / 去阴影 / 对比度增强 / 倾斜校正 / 超分辨率
   └── 针对泛黄、褶皱、墨水褪色等档案特征调参

3. 模型微调
   ├── 基座：PaddleOCR 官方预训练模型（中文识别）
   ├── 方法：在自己的标注数据上 fine-tune 识别模型
   ├── 重点样本：历史手写体（成绩单/名册类）、表格混排文档
   └── 昇腾适配：使用 PaddlePaddle 昇腾版，确保 NPU 加速

4. 后处理优化
   ├── 自定义词典（档案术语、人名、机构名）
   ├── 去重 / 格式化 / 结构化输出
   └── 置信度低于 70% 自动标记"待人工校对"

5. 迭代闭环
   人工校对结果 → 回收入训练集 → 定期（每月）重新微调 → 持续提升
```

### 4.3 Prompt Engineering（审核提示词设计）

训练数据之外，推理时的 System Prompt 同样关键：

```
你是一个档案开放审核专家。你的任务是审核档案全文，
判断是否包含以下敏感信息：

1. 党和国家秘密
2. 未结论的重大问题/事件
3. 学校内部不公开事项
4. 知识产权
5. 个人隐私（身份证号、家庭信息、成绩、健康等）
6. 上级来文和外收文
7. 特定历史时期敏感内容（参考敏感词库）

审核规则：
- 出现上述任一情形 → 建议不予开放或部分开放
- 仅含已公开的学校基本信息 → 建议开放
- 不确定时标明"不确定"，触发人工复核

输出 JSON 格式：
{
  "risk_score": 0-100,
  "risk_level": "低|中|高",
  "sensitive_items": [{"type": "...", "content": "...", "position": [start, end]}],
  "suggestion": "建议开放|建议部分开放|建议延期开放|建议不予开放",
  "reason": "...",
  "confidence": 0.0-1.0
}
```

### 4.4 语义检索的 LLM 应用

检索理解 prompt（非微调，推理时调用）：

```
用户查询："{query}"

请分析查询意图，提取：
1. 核心实体（人名、地名、机构、事件）
2. 查询意图类型（查找具体档案 / 主题研究 / 统计查询）
3. 同义词扩展
4. 建议的 ES 查询字段及权重

输出 JSON...
```
