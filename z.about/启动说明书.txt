一、环境要求
----------------------------------------------
- Python 3.10+（推荐 3.11）
- Node.js 18+
- Windows 10+ / macOS / Linux
- Git
- Docker（可选，用于 ES/MySQL/Redis）
- NVIDIA GPU（可选，用于 PaddleOCR 真实识别）

二、快速启动（Windows PowerShell）
----------------------------------------------
1. 打开 PowerShell，进入项目目录：
   cd archive-system

2. 一键安装依赖（首次运行）：
   .\install.ps1

3. 一键启动前后端：
   .\start.ps1

4. 浏览器访问：
   前端: http://localhost:3000
   后端API文档: http://localhost:8000/docs
   登录: 用户名 admin，密码 Admin@123456
         （开发模式任意账密自动创建，角色 reviewer；admin 固定为 system_admin）

5. 按任意键停止所有服务。

三、仅启动后端
----------------------------------------------
   .\start-dev.ps1
   然后在另一个终端手动启动前端：
   cd frontend
   npm run dev

四、Docker 启动（含 ES / MySQL / Redis）
----------------------------------------------
  docker compose up -d --build
  docker compose --profile ocr up -d   # 可选：启动 PaddleOCR Worker

五、PaddleOCR 部署（可选，需 GPU）
----------------------------------------------
  .\install.ps1 -WithOCR              # 一键部署 PaddleOCR-VL
  python deploy/ocr_env_detect.py     # 检测 GPU/CUDA 环境
  python deploy/ocr_verify.py         # 功能验证（6 项检查）

六、运行测试
----------------------------------------------
  python -m pytest archive-system/backend/tests/ -v
  共 94 个测试用例，全部通过。


七、注意事项
----------------------------------------------

1. 【数据库模式】
   开发环境默认使用 SQLite（文件: backend/archive_dev.db），
   首次启动自动建表 + 种子数据（admin + 5条档案 + 5条预审记录）。
   生产环境设 DB_MODE=mysql 并配置连接。

2. 【AI 模式】
   开发环境 LLM_MODE=mock（规则引擎 + 模拟 LLM 评分）。
   连接真实 LLaMA-Factory 需设 LLM_MODE=real。
   LLaMA-Factory 地址：http://10.11.13.100:7860
   访问方式：向日葵 → 学校主机(10.11.10.32) → 浏览器。
   LoRA 微调配置：train/llm/configs/lora_train.yaml（适配 Qwen2.5-3B + 6GB显存）

3. 【OCR 模式】
   开发环境 OCR_MODE=mock（确定性哈希模拟）。
   真实识别需安装 PaddleOCR：
     .\install.ps1 -WithOCR
     $env:OCR_MODE = "real"
   Docker: docker compose --profile ocr up -d

4. 【Elasticsearch】
   本地无需 ES（自动降级为 SQLite 全文搜索，支持关键词+同义词）。
   生产环境需启动 ES 并运行初始化：
     bash backend/scripts/init_es.sh

5. 【Celery 任务】
   本地无需 Redis（Celery 自动降级为 memory:// 同步执行）。
   生产环境需 Redis + Celery Worker。

6. 【认证机制】
   开发模式：用户名不存在则自动创建（reviewer），密码不校验。
   生产模式：密码校验 + 5次失败锁定15分钟 + 30天密码过期。

7. 【用户权限】
   admin 为 system_admin（全部权限/菜单）。
   角色权限可在「角色权限」页配置（search/ocr/review/sync/user/log/stats 7 模块）。
   目录树授权支持大类→子部门自动继承。
   数据权限（案卷级/卷内级）已强制生效。

8. 【敏感配置】
   .env 文件已加入 .gitignore。生产环境务必修改：
   - JWT_SECRET（随机 32 位字符串）
   - DB_PASSWORD（MySQL 密码）
   - APP_ENV=production

9. 【密码策略】
   不少于 12 个字符。有效期 30 天（生产模式强制检查）。

10.【端口占用】
    后端 8000，前端 3000。冲突时修改 start.ps1 / vite.config.ts。

11.【浏览器兼容】
    Chrome 90+ / Firefox 88+ / Edge 90+。不支持 IE。

12.【主题色】
    主色 #10B981（翡翠绿）。侧边栏点击 Logo 可折叠/展开。

13.【种子数据】
    首次启动自动插入：
    - admin 管理员（system_admin）
    - 3 个预设角色（system_admin / archive_admin / reviewer）
    - 5 条示例档案（含 OCR 全文 + 预审结论）
    - 5 条预审记录
    - 3 个模拟 TIFF 文件（sync_data/ 目录，供下载/预览测试）

14.【GitHub】
    https://github.com/west0006/FileScanLLMOCR.git

15.【Real 模式测试】
    从 mock 切换到真实推理的完整操作步骤见：

    按 L1(ES) → L2(Ollama LLM) → L3(PaddleOCR) → L4(全栈) 逐级验证。
